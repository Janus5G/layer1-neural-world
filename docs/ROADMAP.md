# Roadmap — Implemented Baseline and Optional Community Extensions

This is a historical roadmap and a list of optional ideas for **independent contributors**. It is **not a commitment by the original author to develop further levels**.

**Scope:** Layer 1/1+ source is included. Later levels are NOT implemented, and no scientific or hardware validation is claimed.

## Layer 1 — Neural network, embodiment, and world

**Status:** Implemented in this experimental source tree (behavioral outcomes not scientifically validated).

**Implementation outline:**

- Hand-written MLP with two hidden layers (48 units each).
- Policy head for 11 actions and scalar value head.
- Adam optimizer; A2C with GAE and an entropy bonus.
- A 40-dimensional observation/sensor vector: self-state, genome, food, hazards, mirror, neighbors, mark, curiosity, and global signals.
- Toroidal world with food, hazards, and mirrors.
- Reproduction via genome crossover, neural-weight crossover, and mutation.

**Source files:** `src/neural/network.ts`, `src/world/sensors.ts`, `src/world/types.ts`, `src/world/agent.ts`, `src/world/world.ts`.

**Possible future experiments:** PPO instead of A2C, recurrent policies (LSTM/GRU), regularization such as weight decay or dropout, convolutional perception.

## Layer 1+ — Optional LLM deliberation, mirror-mark task, curiosity

**Status:** Implemented in this experimental source tree (behavioral outcomes not scientifically validated).

**Implementation outline:**

- Local Ollama client using `fetch` rather than an additional npm SDK.
- Novelty-scoring curiosity mechanism and a prediction-error-like signal.
- Mirror-mark action with reward shaping.
- Eleven total actions including `touch_mark` and `seek_novel`.
- Ideas generated by both curiosity heuristics and optional model responses.

**Source files:** `src/cognition/ollama.ts`, and cognition/reward sections in `src/world/world.ts`.

**Possible future experiments:** stronger prompt examples, streaming model output, response caching, and per-agent rather than global request throttling. These were suggestions, **not implemented deliverables**.

## Layer 2 — Persistence between sessions

**Status:** Not implemented in the runnable source. The original design notes included a partial example, not a validated save/load feature.

**Missing work:** complete save/load of weights and optimizer state, episodic memory, reliable restoration of world and agents, and a frozen-agent inspection mode.

**Illustrative API (not implemented here):**

```ts
export async function saveWorld(sim: Sim, filePath: string): Promise<void> {
  // Serialize learned weights and optimizer state, genomes, bonds,
  // ideas and narratives, food, hazards, mirrors, and relevant time/state.
}

export async function loadWorld(filePath: string): Promise<Sim | null> {
  // Reconstruct the world and its agents; validate the file format.
  return null;
}
```

Important considerations:

- Convert `Map` objects to entry arrays before JSON serialization.
- Convert `Float32Array` values to arrays or encode as binary/base64.
- Avoid persisting temporary computational buffers unless recovery requires them.
- Include schema version, file validation, atomic writes, and error recovery.
- The original estimate was **approximately** 2.4 million floating-point values for 120 agents under a particular weight-count assumption, or roughly 10 MB as raw 32-bit floats. This is only a planning estimate, not a measured memory or disk benchmark. JSON and base64 overhead will differ.
- Compact binary formats or a format such as `msgpackr` could be evaluated by contributors.

The original draft contained a persistence sketch, but it is deliberately excluded from the runnable release to avoid suggesting it works.

## Layer 3 — Multiple language-model providers

**Status:** Not implemented in the runnable source. The original notes contained an interface/router sketch only.

**Proposed work:** a common `deliberate(payload)` contract for Ollama, OpenAI, Anthropic, llama.cpp, etc.; optional fallback routing, provider-specific formatting, rate limiting, cost accounting, and an explicit configuration choice.

**Illustrative interface:**

```ts
export interface CognitionProvider {
  deliberate(payload: AgentPayload): Promise<DeliberationResult | null>;
  getStats(): ProviderStats;
  reconfigure(cfg: unknown): void;
}
```

**Important:** Cloud API integrations are ideas only. The Layer 1 baseline is local/offline-first and should not begin transmitting agent data by default. A contributor adding a provider must handle user consent, credential protection, provider-specific message formats, costs, and privacy.

## Layer 4 — Multi-machine communication / ChromaNeural bridge

**Status:** Not implemented. This is an optional, separate concept only. Nothing here should be interpreted as an existing integration or a required dependency.

**Proposed idea:** Independent computers host parts of a simulated world and can, with a carefully designed protocol, exchange agent states or selected experiences across an authorized LAN.

**Proposed messages:**

- `AGENT_SNAPSHOT`: transfer a specific agent state.
- `KNOWLEDGE_SHARE`: transfer an episode or derived information.
- `WORLD_SYNC`: exchange relevant world parameters.

A community implementation would need state schemas, authorization, peer discovery, replay protection, integrity validation, protocol versioning, and conflict resolution. An agent transfer could involve serialization, an authenticated transfer, and validation at the destination.

**Security:** Treat network services as untrusted by default. Do not assume any other project's server is authenticated or safe based on its name. Do not expose a bridge to the public Internet; require a threat model and authenticated, encrypted transport before any network deployment. The separate ChromaNeural project is a historical inspiration in the notes, not part of this released experiment.

## Layer 5 — Metacognitive confidence estimation

**Status:** Not implemented.

**Proposed idea:** Introduce a confidence-estimation head to the `Brain` class. The agent might use low-confidence outputs to select a conservative policy or request optional LLM assistance.

**Illustrative pseudocode:**

```ts
confidenceHead: Linear; // hidden activation -> 1 output, sigmoid
const confidence = sigmoid(this.confidenceHead.forward(this.h2Relu)[0]);
// Track predicted confidence and realized outcomes for calibration.
```

The original notes suggested training against a reward-prediction error or absolute advantage. Confidence would need **empirical calibration**. A high numeric score would not establish self-awareness.

Questions for research: Does calibrated confidence improve decisions? Does behavior differ at high/low confidence? Can confidence predictions become more reliable under an explicit objective?

## Layer 6 — Emergent communication between agents

**Status:** Not implemented.

**Proposed idea:** Instead of supplying all language through an external LLM, add a learnable discrete signaling channel between agents. Signals could be sounds, colors, movements, or other symbols and might develop consistent meanings through cooperative objectives.

**Possible components:** a sensor for a neighbor's latest symbol, a discrete vocabulary (e.g. 16 symbols), send-symbol actions, a cooperative learning signal, and analysis tools measuring symbol-context consistency.

The original proposal suggested rewarding repeated matching symbols in similar contexts. Contributors should be careful: matching alone may reward trivial copying, not meaningful communication. Better tests include cooperative task success, generalization, counterfactual intervention, and robustness across agents/seeds.

**Challenges:** designing a defensible communication reward, very long training horizons, and possible co-evolutionary dynamics.

**Suggested reading:** Kirby, S. (2001), *Spontaneous evolution of linguistic structure*; Steels, L. (2003), *Evolving grounded communication for robots*.

## Layer 7 — PRISME-inspired symbolic color communication

**Status:** Not implemented.

**Proposed idea:** A non-natural-language channel inspired by the separate [PRISME](https://github.com/Janus5G/PRISME) research project. Agents might exchange codes derived from color, intensity, and position rather than natural-language words.

**Proposed work:** adapt a small encoding/decoding model, show optical-style traces in the simulated world, add a receiver decoder and integrity checks, and study whether codes acquire consistent usage.

**Illustrative function names only:**

```ts
encodeSymbol(symbol);
decodeSymbol(encoded);
applyModulo4Parity(data);
```

The source notes also contemplated approximately 28 symbolic choices. **These are speculative design ideas, not statements that PRISME code, hardware, or error correction has been implemented here.** Any protocol details would need to be checked directly against its actual source and separated from the Layer 1 baseline.

Research questions include consistency, emergent structure, and resilience under simulated noise. No hardware-performance claim follows from this experiment.

## Contribution ideas by complexity

| Level | Examples |
|---|---|
| Beginner | Additional actions (`dig`, `build`, `hide`), more sensors, improved agent visualization, better event filters |
| Intermediate | Durable config, full world persistence, additional LLM interfaces, alternative RL algorithms |
| Advanced | Recurrent policies, multi-node synchronization, confidence modeling, emergent communication, symbolic communication |
| Research | Curiosity vs. survival comparisons, mirror-task ablations, generation-to-generation policy diversity, correlation between LLM narratives and measured actions |

Community contributors should isolate changes, make hypotheses testable, avoid implying validated consciousness, and report limitations. The experiment's creator is **not committing to develop these extensions**.
